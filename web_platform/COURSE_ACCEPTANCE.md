# 课程交付与验收

依据助教《金融量化交易平台产品需求文档》，将分阶段要求落实为单账户模拟交易课程版本。以下区分已实现能力、课堂验收动作和边界；不把模拟响应测试当成券商成交证明。

## 课堂可执行流程

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1 | 打开站点，查询 SPY 行情 | Paper 账户与 IEX 行情，数据时间、读取时间和市场状态 |
| 2 | 使用所有者 ChatGPT 身份登录 | 操作员已登录，研究／风控／交易控件可用 |
| 3 | 对账并恢复 | 净值差额和未决订单可查看；通过后可提交 |
| 4 | 选择一种模板，低仓位运行回测 | 真实历史行情生成净值／回撤、成交明细、参数快照；无信号则无交易 |
| 5 | 选择报告，同快照重跑 | 同配置的曲线和指标一致，生成独立实验记录 |
| 6 | 生成订单计划 | 当前／目标股数、方向、价格和有效期；无差额则无需交易 |
| 7 | 预览后确认小额限价 Paper 单 | 服务器重新风控，返回券商订单 ID 与状态；未成交不会显示为已成交 |
| 8 | 撤销未完成订单，执行对账 | 撤单待确认，后续以券商终态为准；外部订单保持原状 |
| 9 | 暂停后尝试预览／提交 | 服务器拒绝新增，刷新后暂停仍存在 |
| 10 | 打开审计并导出 | 风控拒绝、订单意图、券商结果、撤单、对账与控制动作 |

可以选择手动订单，不必等待策略信号。限价低于市场可能长期不成交；休市排队需明确勾选。市价和止损订单要求开市且 IEX 报价新鲜。

## 保存实际成交验收报告

使用所有者账号登录，在「风控与对账」对账并恢复后，打开「交付验收」：

1. 选择标的并点击「检查连接、回测与对账」。平台读取实际 Paper 账户及 IEX 数据、运行回测、重跑快照和对账，保存本次验收基准；这一步不下单。
2. 在五分钟准备期内预览并确认 1 股限价买入。提交时再校验账户、持仓、行情和限额。准备过期则重新准备；已提交的同一验收单仍可查询。休市须明确同意排队，排队不算成交。
3. 点击「创建并撤销独立测试单」，核对 1 股及价格后确认。平台以固定的第二个订单号提交低价买单，接收后申请撤销；重复同一请求不创建新订单。若券商先成交，此项标为未通过，不会假报已撤。
4. 点击「查询成交并更新报告」。网页停留在本页时，也会每 30 秒查询已有验收单。只有券商返回 `filled`、1 股、实际成交均价和时间，独立测试单确认 `canceled` 且零成交，持仓差额与本次成交相符，账户与订单对账通过，才能显示全部完成。
5. 导出汇报文档和原始证据。记录包含委托号、券商订单 ID、价格、时间、检查结论、回测和快照 ID；刷新页面后可在验收记录中重新打开。每次检查独立保存，不覆盖历史检查。

测试成交会留下 1 股持仓，不自动卖出。期间其他同标的操作会影响持仓差额核对。成交后如需结束课程交易，可从模拟交易页另行卖出已持有股份并对账。限价单不保证成交；未成交时继续等待或撤销后准备新验收，不能把待完成报告用于声称成交验证通过。

## 工程验证

- Python 原项目：29 项全量测试通过。
- 新网页平台：35 项 Node 测试，使用 SQLite 与 HTTP 券商替身。覆盖认证、来源校验、因果回测、快照重跑、并发租约、幂等、超时恢复、数据库失败、资金约束、行情过期、排队、撤单终态、暂停／恢复并发、计划过期／持仓变化、对账与摘要，以及九项验收结论、报告持久化和跨开市撤单恢复。
- 真实 Workerd 运行时通过券商传输回归，含 POST／DELETE 请求兼容性、重定向拒绝、404 与凭据脱敏；使用本地服务绑定，不向 Alpaca 发送订单。
- ESM 产物加载与资源入口验证。实际成交和浏览器端验收需在站点按上表完成；本地测试不调用券商交易服务。

## PRD 边界

参考 PRD 包含机构多租户、组织协作、角色体系扩展、多市场、机构行情管理、任意策略开发环境、AI 编排、高频、后台自动交易和高级算法执行。此版完成「研究 → 计划 → 手动确认 Paper 执行 → 风控 → 对账」课程流程，以上扩展没有被宣称为已实现。

## API 与持久化

接口前缀 `/api/v1/`。GET：`session`、`overview`、`market`、`equity`、`catalog`、`artifacts`、`artifact`；`audit` 需要操作员。POST：`backtests`、`plans`、`plans/submit`、`orders/preview`、`orders`、`orders/cancel`、`orders/cancel-all`、`control`、`risk`、`reconcile`；全部要求操作员和同源 JSON 请求。

验收接口：GET `acceptance/report?id=...` 读取已保存的记录；POST `acceptance/prepare`、`acceptance/submit`、`acceptance/cancel-check`、`acceptance/inspect` 依次准备、下单、独立撤单和刷新证据，均遵循原操作员认证和订单引擎约束。

四张 D1 表：`control` 保存开关、限额、身份和租约；`orders` 保存意图与券商关联；`artifacts` 保存数据／策略／回测／计划／验收基准与检查报告；`events` 保存追加式审计。迁移与源码存档，凭据只在站点服务端运行时配置。
