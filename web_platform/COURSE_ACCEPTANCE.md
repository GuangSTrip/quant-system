# 课程交付与验收

依据助教《金融量化交易平台产品需求文档》，将分阶段要求落实为单账户模拟交易课程版本。以下区分已实现能力、课堂验收动作和边界；不把模拟响应测试当成券商成交证明。

## 课堂可执行流程

| 步骤 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 1 | 打开站点，查询 SPY 行情 | Paper 账户与 IEX 行情，数据时间、读取时间和市场状态 |
| 2 | 使用所有者 ChatGPT 身份登录 | 操作员已登录，研究／风控／交易控件可用 |
| 3 | 对账并恢复 | 净值差额和未决订单可查看；通过后可提交 |
| 4 | 选择一种模板，低仓位运行回测 | 真实历史行情生成净值／回撤、成交明细、参数快照；无信号则无交易 |
| 5 | 选择报告，同快照重跑 | 同配置的曲线和指标一致，生成独立实验记录 |
| 6 | 生成订单计划 | 当前／目标股数、方向、价格和有效期；无差额则无需交易 |
| 7 | 预览后确认小额限价 Paper 单 | 服务器重新风控，返回券商订单 ID 与状态；未成交不会显示为已成交 |
| 8 | 撤销未完成订单，执行对账 | 撤单待确认，后续以券商终态为准；外部订单保持原状 |
| 9 | 暂停后尝试预览／提交 | 服务器拒绝新增，刷新后暂停仍存在 |
| 10 | 打开审计并导出 | 风控拒绝、订单意图、券商结果、撤单、对账与控制动作 |

可以选择手动订单，不必等待策略信号。限价低于市场可能长期不成交；休市排队需明确勾选。市价和止损订单要求开市且 IEX 报价新鲜。

## 工程验证

- Python 原项目：29 项全量测试通过。
- 新网页平台：27 项 Node 测试，使用 SQLite 与 HTTP 券商替身。覆盖认证、来源校验、因果回测、快照重跑、并发租约、幂等、超时恢复、数据库失败、资金约束、行情过期、排队、撤单终态、暂停／恢复并发、计划过期／持仓变化、对账与摘要。
- ESM 产物加载与资源入口验证。实际成交和浏览器端验收需在站点按上表完成；本地测试不调用券商交易服务。

## PRD 边界

参考 PRD 包含机构多租户、组织协作、角色体系扩展、多市场、机构行情管理、任意策略开发环境、AI 编排、高频、后台自动交易和高级算法执行。此版完成「研究 → 计划 → 手动确认 Paper 执行 → 风控 → 对账」课程流程，以上扩展没有被宣称为已实现。

## API 与持久化

接口前缀 `/api/v1/`。GET：`session`、`overview`、`market`、`equity`、`catalog`、`artifacts`、`artifact`；`audit` 需要操作员。POST：`backtests`、`plans`、`plans/submit`、`orders/preview`、`orders`、`orders/cancel`、`orders/cancel-all`、`control`、`risk`、`reconcile`；全部要求操作员和同源 JSON 请求。

四张 D1 表：`control` 保存开关、限额、身份和租约；`orders` 保存意图与券商关联；`artifacts` 保存数据／策略／回测／计划；`events` 保存追加式审计。迁移与源码存档，凭据只在站点服务端运行时配置。
