# 后台自动模拟交易

平台支持一个账户同时运行一个授权的预置策略：开盘区间突破、VWAP 均值回归，以及旧版双均线、绝对动量、买入持有。分钟策略读取 Alpaca IEX 1Min 行情，旧版策略读取日线；在常规开市期间经过服务端风控后提交 Alpaca Paper 限价单，后台跟踪券商订单与持仓。关闭网页或退出网站不会停止策略。

## 使用流程

1. 在「策略与回测」运行并保存一份真实行情回测。在「风控与对账」完成对账并恢复全局交易。
2. 打开「自动策略」，选择回测报告，输入独立预算，再输入“启动自动模拟交易”并启动。首次启动要求所选标的没有持仓与未完成委托。预算不超过全局单笔限额。
3. 等待后台执行；课堂可点击「立即检查一轮」执行同一服务端流程。该按钮可能真实提交模拟订单。查看后台记录、订单状态和券商成交回报，导出运行证据。

分钟策略与回测使用相同的策略预算与信号规则；开盘区间突破在开盘观察期后突破上沿买入、跌破区间中点卖出，VWAP 均值回归在低于当日 VWAP 阈值时买入、回到 VWAP 卖出，两者均在美东时间 15:45 后发出平仓信号。旧日线策略仍按报告信号和独立预算交易。每根完整行情最多做一次决策。成交价、成交时间和未成交均以券商为准，固定限价不会持续追价重挂。

## 启停与恢复

「暂停策略」停止后续新订单，不自动平仓，也不保证已发出委托被撤回。「暂停并撤销策略挂单」只申请撤销该策略的未完成委托；已成交部分无法撤销。暂停与提交并发时，在券商确认接收后再次检查运行状态，对仍未终结的订单申请撤销。

全局暂停同时停止自动策略；恢复全局交易后，策略仍需单独授权恢复。未知订单、日亏损、对账不一致、资料缺失或执行异常会暂停策略；先查订单并对账，再恢复。上轮执行中断时不自动抢占租约，需等待超时后人工对账恢复。失败或已处理的同日决策不会换一个订单号盲目重试。

自动策略运行期间，同标的手动下单会被拒绝，需先暂停。外部券商操作、拆股或其他变化造成真实持仓与策略成交账本不同，也会暂停，避免误卖非策略持仓。新建另一策略运行前需要所选标的重新清空；暂停后可通过手动交易处理余仓。

## 调度部署

当前 Sites 站点由本仓库 `.github/workflows/paper-scheduler.yml` 驱动，工作日 UTC 13–21 时每 10 分钟检查，所有日期每小时第 17 分钟另发一次心跳。覆盖美股冬夏令时常规时段，实际是否开市以 Alpaca 时钟为准。分钟策略的行情频率是 1 分钟，但此站点的自动检查约 10 分钟一次；若最近完整分钟线超过 5 分钟，本轮只记录等待，不下单。GitHub 可能延迟或跳过调度，它不是实时撮合或高可用交易系统；后台心跳超过 75 分钟则显示异常，但不阻止新启动／恢复。网页显示实际心跳和执行时间。

任务使用 GitHub OIDC 短时身份，仅能调用调度接口，不能更改策略或代替登录用户授权启动。服务端校验签名、时效、发行者、受众、仓库和所有者不可变 ID、main 分支、固定工作流路径、事件类型和 subject。无需把 Alpaca 密钥或网站密码写进 GitHub。仅原仓库 ID 的任务运行；组员复制或 fork 后不会触发原账户。GitHub Actions 额度由仓库账户管理，额度不足或 Actions 被关闭会中断后台检查。

组员执行 `npm run deploy` 时，Wrangler 自动配置 Cloudflare 原生 `*/5 * * * *` Cron 与 `SCHEDULER_NATIVE=true`，无需另建 GitHub 定时任务。部署后可先保存启动授权并手动检查一轮，Cron 变更可能需要传播时间。原生 Cron 调用相同执行器。

原 Sites 调度配置为非秘密环境项 `SCHEDULER_REPOSITORY`、`SCHEDULER_REPOSITORY_ID`、`SCHEDULER_OWNER_ID`、`SCHEDULER_AUDIENCE`，API 为 `POST /api/v1/scheduler/tick`，必须提供经验证的 OIDC 身份。策略管理和手动执行 API 仍需网站登录与同源检查。

## 数据与验收

配置从不可变回测报告复制，每次新运行有独立运行编号。执行决策先持久化，再通过原订单引擎提交；数据快照、参数、信号、引擎版本、订单号和券商回报可以追踪。数据库并发租约、每日决策唯一键和原订单幂等键共同阻止重叠执行重复下单。页面展示最近 60 轮，保留最近 1,000 轮运行日志；决策、数据快照和订单记录持续保存。

自动化测试覆盖后台调用、开休市转换、去重、并发、暂停竞态、未知订单、外部持仓变化、亏损熔断、日线信号买入和退出、存储故障以及 OIDC 签名与身份拒绝。测试券商替身的成交不代表在线账户成交。最终在线验收需要记录后台心跳，并在开市后保存实际自动订单的券商接收／成交回报；未开市时只能验证等待状态和调度连通。

本次实现针对课程模拟盘。机构多租户、任意代码沙箱、Tick／订单簿策略、AI 自主调整与真实资金交易不属于该实现。分钟策略收盘前发出限价平仓委托，但委托可能不成交；应在订单页确认实际状态，不能把回测平仓当成 Paper 已平仓。

依据：[GitHub OIDC](https://docs.github.com/en/actions/reference/security/oidc)、[GitHub 定时事件限制](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)、[Cloudflare Cron](https://developers.cloudflare.com/workers/configuration/cron-triggers/)。

## 心跳过期时的网页操作

后台近期未响应时，仍可授权启动或恢复，然后点击「立即检查一轮」执行既有 Paper 策略流程。启动授权本身不提交订单；手动检查可能提交。登录、确认文字、全局暂停、预算、空仓、对账、行情与订单风控保持生效。手动检查不刷新后台心跳，不能证明关闭网页后持续运行；后台调度延迟问题独立保留提示。

## 可配置金额限额

策略预算与单笔限额不再设固定 10,000 USD 上限，单日限额不再设固定 50,000 USD 上限。操作员在「风控与对账」保存所需金额；策略页显示当前真实单笔限额并据此校验预算。单日额度仍不得小于单笔额度。金额须为至少 100 的有限数值，并在可安全表示到分的数值范围内。现有资金、持仓、单日累计、日亏损、订单数量及幂等检查不变；本次修改不会自动提高已保存的账户风控额度。
