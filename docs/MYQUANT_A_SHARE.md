# A 股掘金仿真交易

已合并网页 A 股交易通道，同时保留淡黄色界面和统一策略中心。A 股页面支持账户、持仓、限价单预览／提交、撤单、暂停和对账。它是独立的手工仿真交易通道，尚未接入 178 个组合的 A 股自动调仓，也不增加分钟行情或回测能力。

## 模拟环境与运行方式

合并时移除了 `gm` 的 `MODE_LIVE` 入口：实时模式并不能证明绑定的是仿真账户。当前入口使用官方 `gmtrade` SDK，固定连接官方仿真服务 `api.myquant.cn:9000`，不允许网页或环境变量覆盖服务地址，不回退连接终端或真实券商。

依据：[掘金官方仿真 Python 接口](https://sim.myquant.cn/sim/help/Python.html)。SDK 仅在启动入口时导入，安装应遵照官方支持的运行平台。本次没有连接真实仿真服务；SDK／账户的实际兼容性与成交回报仍需在用户自己的环境验收。

1. 在仿真服务申请账户，在支持的本机 Python 环境安装 `gmtrade`。
2. 设置以下本机环境变量，不要写入仓库或网页：

| 变量 | 用途 |
|---|---|
| `MYQUANT_SIM_TOKEN` | 官方仿真服务 token |
| `MYQUANT_SIM_ACCOUNT_ID` | 对应仿真账户 ID |
| `MYQUANT_BRIDGE_SECRET` | 本机与网页服务共享的高熵密钥 |
| `MYQUANT_BRIDGE_STATE_PATH` | 可选，SQLite 状态路径，默认 `.myquant_bridge_state.sqlite` |
| `MYQUANT_BRIDGE_MAX_ORDER_NOTIONAL` | 可选，单笔限额，默认 100000 元 |

3. 运行 `python -m quant_system.myquant_strategy`。无需旧版 `MYQUANT_STRATEGY_ID`。本机桥接仅监听 `127.0.0.1:8765`，SDK 调用串行执行，每秒轮询订单和账户。
4. 在自己的服务器上配置 `MYQUANT_BRIDGE_URL`（仅 HTTPS origin）与 `MYQUANT_BRIDGE_SECRET`。远端访问本机需自行配置受保护的 HTTPS 隧道；本次没有建立隧道或部署。
5. 登录网页，在「A 股交易」读取账户、对账，再输入 `恢复A股模拟盘`。每次桥接启动默认暂停。下单需要预览后输入 `提交A股模拟订单`。

本地 `scripts/demo.mjs` 是隔离演示环境，未配置可用 A 股桥接时显示不可用；不能据此声称已通过外部成交验收，也不会自动把本机秘密转交给外部服务。

## 风控与数据边界

- 买入按 100 股整手，零股卖出只允许全部可卖数量；没有有效可卖字段时阻止卖出，不用总持仓推断 T+1 可卖数量。
- 可用现金缺失、非有限值或只有账户净值时拒绝买单。价格非有限值也拒绝。
- 仿真服务固定账户隔离，未验证服务环境禁止新订单。限价、整手、单笔金额与实际券商回报共同约束交易，未实现全部板块特殊申报规则。
- 订单意图先保存，未知回报暂停且不自动重发。重启后重新对账，日内全部委托用于恢复已结束的订单状态；更早的未知记录需人工核查。
- 暂停不等于撤单。已接收订单仍可能成交，撤单必须跟踪最终回报。
- 网页退出登录清空 A 股私有数据，并丢弃退出前发起但随后返回的账户请求；A 股页面不显示美股账户状态。
- A 股订单状态定义与美股分离，避免改变原美股撤单按钮语义。
