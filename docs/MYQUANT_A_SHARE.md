# A 股掘金实时模拟盘桥接

本项目将掘金量化的策略运行时与网页分开：`gm` SDK 只在安装掘金终端的本机 Python 进程中执行；网页和 Cloudflare Worker 不接收、不保存、也不返回掘金 token。这样可以保留网页登录、订单回报、对账和审计，同时避免把交易凭证交给浏览器。

## 组成与边界

```text
网页（平台账号密码）
        │ HTTPS + Worker 秘密
        ▼
Cloudflare Worker ── HTTPS 隧道 ── 本机 MyQuantBridge
                                         │ 仅策略回调线程调用
                                         ▼
                                  掘金 gm SDK / A 股仿真账户
```

- 现有网站账号密码继续用于 A 股页面；它不是掘金账号，也不是 token。
- 本机桥接默认只监听 `127.0.0.1:8765`，不应直接开放端口到公网。
- 首版只允许 A 股限价单：买入必须是 100 股整手；卖出仅在全卖可用持仓时允许零股。这样可以在提交前可靠检查金额、可用现金与 A 股 T+1 可卖数量。
- 下单意图会先持久化到本机 SQLite；SDK 无回执、网络异常、桥接重启前的待处理意图都会标记为未知并暂停，不会自动重发。
- 暂停不等于撤单。已被掘金接受的订单可能继续成交；需要在订单表中逐笔申请撤单，再查询最终回报。

## 本机准备

1. 在掘金终端中安装并选择当前 Python 的 `gm` SDK，创建一个策略并绑定**仿真**账户。不要把真实账户绑定给本策略。
2. 为运行策略的 Windows 用户环境变量设置下列值（值均不应提交到 Git）：

   | 变量 | 保存位置 | 说明 |
   | --- | --- | --- |
   | `MYQUANT_SIM_TOKEN` | 本机 | 掘金策略 token |
   | `MYQUANT_SIM_ACCOUNT_ID` | 本机 | 已绑定的掘金仿真账户 ID |
   | `MYQUANT_STRATEGY_ID` | 本机 | 掘金终端为本策略生成的策略 ID |
   | `MYQUANT_BRIDGE_SECRET` | 本机和 Worker secret | 随机、高熵的桥接共享密钥 |
   | `MYQUANT_BRIDGE_STATE_PATH` | 可选，本机 | SQLite 状态文件路径；默认项目目录 `.myquant_bridge_state.sqlite` |
   | `MYQUANT_BRIDGE_MAX_ORDER_NOTIONAL` | 可选，本机 | 单笔人民币金额上限；默认 `100000` |

   `MYQUANT_BRIDGE_SECRET` 应使用密码管理器或安全随机数生成器创建。它与 token 不同，但同样不能放入源码、截图、Issue 或聊天记录。

3. 在项目根目录的同一终端中启动策略桥接：

   ```powershell
   python -m quant_system.myquant_strategy
   ```

   成功后策略会连接掘金，读取绑定账户，并在 `127.0.0.1:8765` 启动桥接。不要同时运行同一账户的多个桥接副本。

4. 先在掘金终端和网页 A 股页面确认账户、现金、持仓均能读到。首次状态必须显示“已暂停”；点击“立即对账”，没有未决订单后再输入 `恢复A股模拟盘` 恢复。恢复前不要尝试下单。

## 公开网页部署

网页部署到公网时，Worker 无法直接访问你的 `127.0.0.1`。需要由你在桥接机器上配置一个经过身份保护的 HTTPS 隧道（例如 Cloudflare Tunnel），将**单个本机桥接服务**暴露为 HTTPS 地址。不要把桥接服务改为 `0.0.0.0` 后直接做端口映射。

在部署 Worker 的环境中把以下两项设为秘密变量，而不是写入 `.env.example`、网页配置或 Git：

```text
MYQUANT_BRIDGE_URL=https://你的桥接隧道域名
MYQUANT_BRIDGE_SECRET=与本机完全相同的随机密钥
```

Worker 只接受 HTTPS、无用户名密码、无路径的桥接地址，并且只允许调用固定的状态、订单、撤单、对账和控制接口。设置后重新部署 Worker；网页登录功能已经存在，无需创建第二套掘金网页登录。

## 日常操作与故障处理

1. 登录网页的操作员账号，打开「A 股实时模拟盘」。
2. 确认桥接已连接、账户与持仓已读取，执行对账；状态正常后恢复。
3. 以少量 A 股限价单进行预览，逐项核对代码、方向、数量、限价和估算金额，再输入 `提交A股模拟订单`。这会创建真实的**掘金仿真**委托，不是网页演示。
4. 在订单表跟踪掘金回报；成交、部分成交、撤单申请和撤单完成是不同状态。发生超时或未知状态时，不要换新的订单号重试，先对账。
5. 完成演示后暂停新增委托，并处理未完成订单。

桥接本机必须保持运行才能读取实时状态或提交仿真订单。隧道、策略或网络断开时，网页会显示桥接不可用；本机已有委托的最终状态需要在掘金终端和网页对账后确认。该适配器只针对模拟盘，不构成真实资金交易支持。

## 本地网页端到端测试

不必先发布 Worker，也可用项目的本地演示服务器验证网页到掘金仿真账户的完整链路。美股页面仍使用本地替身；只有 A 股请求会经隧道到掘金桥接。

1. 在终端一启动 `python -m quant_system.myquant_strategy`，确认桥接监听在 `127.0.0.1:8765`。
2. 在终端二启动仅用于测试的临时 HTTPS 隧道，例如：

   ```powershell
   cloudflared tunnel --url http://127.0.0.1:8765
   ```

   记下它打印出的 `https://*.trycloudflare.com` 地址。这个临时地址随进程结束失效；测试结束后按 `Ctrl+C` 关闭隧道。不要把地址或桥接共享密钥发给他人。
3. 在终端三进入 `web_platform`，把刚才的地址和本机同一个桥接密钥仅设置到当前 PowerShell 进程，然后启动网页：

   ```powershell
   $env:MYQUANT_BRIDGE_URL = 'https://你的临时隧道地址'
   $env:MYQUANT_BRIDGE_SECRET = '你的桥接共享密钥'
   node scripts/demo.mjs
   ```

   打开 `http://127.0.0.1:8787/#cn-trade`，使用演示账号 `course_test` 和密码 `fixture-only-password-123` 登录。
4. 首先只点击“刷新状态”和“立即对账”：应看到“掘金桥接已连接”、账户与持仓信息，以及默认“已暂停”。这一步不下单。
5. 输入 `恢复A股模拟盘` 恢复后，可先使用 100 股限价单进行“检查并预览”，仍不会下单。确认页面字段、金额、整手和可卖规则正确后，才输入 `提交A股模拟订单` 创建一笔掘金**仿真**委托。随后在订单表检查回报；可申请撤单并再次对账。若只验证整条订单链路，使用较低且不易成交的限价，并在掘金最终回报为 `canceled` 后结束测试。

Cloudflare 的 Quick Tunnel 会为本机服务生成临时 `trycloudflare.com` HTTPS 地址，适合开发测试；它不是生产通道。[Cloudflare 官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)

## 验证范围

本仓库的桥接单元测试覆盖订单格式、A 股整手／可卖规则、资金上限、幂等意图、SDK 回报写入和未知失败自动暂停；网页代理测试覆盖 HTTPS 限制及密钥仅转发到桥接。测试不使用掘金凭证，也不会创建模拟订单。首次实际下单应由操作员在网页确认后单独完成。
