## 已改动的入口

- `web_platform/src/minute-library.mjs`：三策略信号、下一根分钟线开盘价模拟成交、资金/基准/回撤、交易记录；区分美港 A 时段、港/A 午休、整手和 A 股 T+1。当前每市场固定一个成本基点值，这是教学近似。
- `web_platform/scripts/build-library-demo.mjs`：生成 9 份默认报告；读取 `demo-data/library-inputs/` 中的可选本地真实快照，按市场和代码替换默认样本或新增标的；输出 `src/library-demo.json`。`scripts/build.mjs` 自动运行它。
- `web_platform/src/index.html`、`src/app.js`、`src/styles.css`、`src/assets.mjs`、`src/server.mjs`：策略库页面、对照表、资金/回撤/买卖点曲线与静态报告服务。对照表位于单策略选择之前。
- `web_platform/demo-data/SPY-1Min-snapshot.json`：短期公开历史快照；`scripts/fetch-demo-data.mjs` 可更新演示快照。Yahoo Chart 非正式数据接口，不应依赖它作为长期生产来源。
- `web_platform/scripts/demo.mjs`：本地课堂演示；它给原有美股 Paper 流程注入历史行情与券商替身，不会连接 Alpaca Paper。
- `web_platform/tests/minute-library.test.mjs` 和 `tests/intraday.test.mjs`：研究库及原有分钟流程的回归检查。

## 真实数据接手步骤

1. 与数据负责人确认美、港、A 股分钟历史数据的权限、覆盖期、交易日历、时区、复权和成交量单位。Alpaca 凭证只用于美股 Paper/数据；不要假定能提供港/A 股数据。不要把密钥发进聊天、提交到 Git 或打包进网页。
2. 每个标的准备一个 JSON 文件，放在被 Git 忽略的 `web_platform/demo-data/library-inputs/`。最小格式和字段见 [web_platform/README.md](../web_platform/README.md) 的“接入其他真实分钟数据”段。`market` 取 `US`/`HK`/`CN`，`timeframe` 必须为 `1Min`，`sample_kind` 为 `historical`。时间戳建议带时区偏移。该标签仅是声明，不能证明来源真实。
3. 在 `web_platform` 下运行 `npm run build`、`npm test`、`npm run validate`，然后 `node scripts/demo.mjs` 打开 `http://127.0.0.1:8787/#library`。确认新标的进入下拉框，三份报告、曲线、成交和来源标签都对应同一份数据。报告在**构建时**生成；仅复制文件而不重新构建，网页不会更新。
4. 补数据 QA：重复/缺失分钟、非交易时段、停牌、拆股/分红、价格异常、交易日历和跨时区日期。当前引擎只过滤一部分无效 OHLCV，并检查至少两日、每天至少 40 根有效线；这不足以保证真实回测可信。应将原始文件、清洗规则和最终报告的时间范围一起记录。
5. 冻结股票池、参数和成本假设；在不同时间段及多个标的上做样本外回测，对照同预算基准，报告收益、回撤、交易次数及成本敏感性。亏损如实保留，不用现有 5 日样本挑盈利参数。A 股还需核实 T+1、涨跌停、印花税与费用；港股需按标的核实每手股数、费用及交易日历。当前定额基点和固定 100 股整手只是近似。
6. 向模拟盘组员移交固定的策略 ID、规则、参数、数据格式、预期信号和回测样例。由其负责对齐执行规则、选择模拟交易通道，并验收订单接收、成交和对账。现有调度不保证每分钟运行，不能把分钟级研究直接宣称为低延迟实盘高频执行。
