# 实盘上线清单

当前 `PaperBroker` 用于确定性验证订单状态和部分成交逻辑；`AlpacaPaperBroker` 已接入 Alpaca 的 paper 域，支持账户/时钟/持仓读取、最新 bid/ask、日线下载、订单幂等恢复、订单轮询、撤单、仓位对账、重试、审计日志与本地 kill switch。

Alpaca 纸面交易操作协议：

1. 使用独立 paper credentials，放入 `ALPACA_PAPER_API_KEY` 和 `ALPACA_PAPER_API_SECRET` 环境变量。
2. 保持 `paper_trading.enabled: false`，先执行 `--paper-status` 和 `--paper-plan`；两者无下单副作用。
3. 复核审计日志、目标权重和仓位差异后，才将该开关设为 `true`，并在开市时使用 `--confirm-paper-orders`。
4. 出现数据异常、账户不一致或人工判断需要停止时，执行 `--paper-halt`。它会阻止此系统后续提交，直至显式 `--paper-resume`。
5. 每次 `--paper-status` 都读取账户、仓位与本策略未完成订单；订单提交后保存预期仓位，后续状态检查自动调用 `reconcile()` 并报告差异。差异只作为人工处理告警，系统绝不自动清仓未知仓位。

注意：Alpaca 的 paper 域与真实域的 URL 和凭据不同；本项目的适配器将交易端点固定为 `https://paper-api.alpaca.markets`。报价使用配置中的 `iex`（可改为有权限的 `sip`/`delayed_sip`），因此课堂展示应注明数据源与权限差异。

接真实资金前还必须完成：

- 真实券商 sandbox 适配与账户/持仓/现金双向同步。
- 幂等订单编号、超时重试、撤单竞争和重复回报去重。
- 交易所日历、时区、休市、盘前盘后和公司行动。
- 启动时对账、盘中定时对账、收盘后逐笔成交对账。
- 独立进程级风险：单笔、单日、单标的、总敞口和亏损限额。
- 数据延迟/缺失/跳变监控，券商断线与行情断线熔断。
- 密钥使用系统密钥库或环境注入，绝不写入仓库和日志。
- 结构化日志、指标告警、审计追踪、版本与配置回滚。
- 模拟盘至少覆盖多个再平衡周期，并核对理论成交与实际成交差异。
- 小资金灰度、人工 kill switch、明确的故障联系人和恢复手册。

策略进程不得拥有绕过券商侧限额的能力。真实订单连接应作为单独、显式开启的部署配置，默认必须保持关闭。
