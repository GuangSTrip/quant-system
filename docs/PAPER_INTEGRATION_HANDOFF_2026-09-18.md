# 给模拟盘接入组员的交接

日期：2026-09-18。先读 [策略总结](STRATEGY_SUMMARY_2026-09-18.md)。本文件交付接入依据与任务清单，不表示策略已经接上模拟盘。本轮没有执行新订单或发送组员消息。

## 1. 从哪里开始

当前候选是多股票组合；现有网站 `web_platform/src/engine.mjs`、`server.mjs` 和 `automation.mjs` 的计划/自动策略主要面向单标的和固定白名单。不能把研究报告的 `selected` 直接提交给 `/api/v1/plans` 或 `/api/v1/automation/start`。

建议先在本地账户替身完成目标仓位与订单链路验证；若沿用现有 Alpaca Paper 适配代码，可从美股候选开展集成。当前工程没有已完成的 A 股、港股券商适配，不应把这两市场的代码发给现有美股接口。港股历史表现较好与接入便利程度是两件分别需要验收的事。

## 3. 要锁定的策略语义

精确配置见总结表；每市场独立预算 100 万本币。研究候选通常无杠杆、不做空，股票目标最多 80%，余下现金不计利息。

- CN：`smooth_momentum / trend / vol08 / None`，历史动态前 30 只；需保留新增 A 股选股过程。
- HK：`near_high / monthly / inverse_vol / risk06`，动态前 20 只。
- US：`near_high / breakout / inverse_vol / None`，动态前 20 只。

收盘后使用完整日线产生信号，下一交易日开盘模拟执行，不能用当天最终成交量判断当天开盘可成交。历史模型使用前一交易日成交额的 1% 限制成交，并跳过低于总权益 0.05% 的微小调整。费用单边 CN 0.15%、HK 0.20%、US 0.10%，是研究合并成本假设，不是已查询的实际费率。

每 21 个本市场交易日重选，不是每个自然月固定日期。8% / 6% 波动规则每 5 个交易日更新；重选或激活股票集合变化也会重算目标。美股通道规则要保留持有状态：未跌破退出线时不能因今日没有再次突破就卖出。通道高低点排除当日，均线含已完成的当日收盘。

波动倒数分配先在整个入选名单上分配最多 80%、单股目标上限 10%，再把未激活部分留现金；不要擅自把未激活的预算再分给其他股票，否则会改变风险与回测结果。实际权重会随价格漂移。

预热起点、21 日换股相位和 5 日风险更新相位必须固定并持久化，不能每次重启以“今天”为第零天。建议对照历史同一日期逐项比对名单、激活状态、目标权重。

## 4. 待实现的组合信号接口

下面是**建议约定，尚未实现的 API**。策略层输出目标仓位，接入层结合真实账户计算差额。不要让策略层假设空仓生成重复买单。

建议一份信号至少包含：

| 字段 | 含义 |
|---|---|
| `schema_version`、`strategy_version`、配置摘要 | 固定格式及可追溯的策略版本 |
| `market`、`currency`、账户标识 | CN/CNY、HK/HKD、US/USD，避免跨币种混算 |
| `signal_date`、`data_asof`、输入数据摘要 | 信号所属收盘日及已使用数据的边界 |
| `execute_session`、`expires_at` | 预计下一市场交易时段及明确失效时间 |
| `targets[]` | 证券代码、0—1 的目标权重、入选排名和买卖原因；不是百分数 0—100 |
| `cash_weight` | 1 减目标股票权重之和 |
| `rebalance_reason`、状态摘要 | 重选/进出变化/风险更新及可重放状态 |

名单落选且由本策略管理的持仓应明确输出目标 0；不得自动清仓其他策略或人工持仓。数据不完整时应返回“信号不可用”及原因，不能把空数组误当成全卖出。

当前 `simulate()` 没有导出每日完整目标权重、逐笔成交账和可恢复状态。需要将其逐日决策部分抽为可重放的函数，保留现有回测作为对照；不得从净值曲线反推出目标仓位。

## 5. 从目标仓位到订单

接入组负责以下流程：

1. 更新当前账户现金、权益、持仓、未完成委托；确认最新完整行情和交易日历。
2. 将研究符号映射到券商证券 ID，检查可交易状态、币种与每手数量。港股每手数量不能固定写成一个通用值；A 股按证券规则区分可买和可卖数量。
3. 用未复权可交易价格将目标金额换为真实股数，扣除费用与现金缓冲。研究使用复权可分割份额，不得直接当真实股票数量。
4. 按目标持仓减当前持仓，并处理未完成委托，生成差额订单；不得对同一信号重复加仓。
5. 先检查可卖持仓及资金释放，再安排买单；部分成交、撤单、拒单、未成交均需要后续对账。
6. 沿用服务器预检、提交、幂等标识、审计和暂停机制。失败或未知订单应先查状态，不能盲目重发。
7. 用实际成交回报更新账户和策略状态；提交成功不等于成交。

A 股需按真实规则处理 T+1 可卖库存、停牌、涨跌停、ST 与不同板块；现有回测的 ±4.8% 开盘缺口保护只是保守近似。各市场交易日历、时区、费用和公司行动需要分别实现。若不能在开盘按研究假设成交，应记录实际执行方式，并按一致假设重验，不要沿用原收益结论。

## 6. 已有 HTTP 路由可以复用什么

| 路由 | 当前用途 |
|---|---|
| `GET /api/v1/overview` | 原适配账户、持仓和订单概况 |
| `POST /api/v1/orders/preview` | 单笔订单预检 |
| `POST /api/v1/orders` | 提交单笔订单 |
| `POST /api/v1/orders/cancel` | 撤单请求 |
| `POST /api/v1/reconcile` | 对账 |
| `POST /api/v1/control` | 暂停等控制 |
| `POST /api/v1/plans`、`/plans/submit` | 旧单标的回测计划，不支持本轮组合直接输入 |

具体请求体和鉴权以 `server.mjs`、`auth.mjs` 为准。现有 `SYMBOLS` 白名单只有少量预置美股/ETF，与动态股票池不一致；需要券商可交易资产校验及策略允许范围的适配，不能简单删掉白名单来绕过限制。原风控默认单笔/当日金额也可能远小于 100 万预算，需明确组合预算、拆单安排和批准后的风险限额。

## 7. 接入验收清单

- 相同历史日的研究选股、信号和适配器目标权重一致；旧曲线能复现。
- 重启后调仓日历、通道状态、净值高点等状态不丢失；同信号重试不重复下单。
- 落选股票正确减仓；其他策略持仓不受影响；数据缺失不触发错误清仓。
- 现金不足、部分成交、涨跌停/停牌、拒单、超时与未知状态均有明确处理。
- 按真实成交回报对账，报告计划与实际权重、成本和跟踪误差。
- 本地替身测试和外部券商 Paper 成交证据分别标记，不混用。

A 股候选对延迟成交敏感；美股成本加倍后年化降至 7.09%。这些限制要随策略一并交付，不能只展示基础场景。交接期间不需要启动任何真实或模拟委托。

部署前置和原平台验收另见 `web_platform/DEPLOY.md`、`AUTOMATION.md`、`COURSE_ACCEPTANCE.md`。不随交接文件传递本机 Tushare Token 或券商凭据。
